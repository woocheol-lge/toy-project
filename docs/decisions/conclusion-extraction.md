# 논의사항에서 결정사항 뽑기

## Decisions

- 회의 중에는 "논의사항"이라는 자유 형식 글만 적는다. "결정사항"이라는 별도
  입력칸은 없다.
- 회의가 끝나면(종료 화면, 마크다운 반출 모두) 그 논의사항의 마지막 줄(줄이
  하나뿐이면 그 줄 안의 마지막 문장)을 결정사항으로 뽑아 함께 보여준다.
- 뽑아내는 방식은 순수 텍스트 처리다. 목록 표시(`-`, `1.`, `2)` 등)만 걷어내고,
  그 외에는 원문을 그대로 쓴다. AI나 외부 서비스를 부르지 않는다.
- 자동으로 뽑은 결정사항을 진행자가 연필 아이콘으로 직접 고칠 수 있다. 고친
  값을 비우면 다시 자동으로 뽑은 값으로 돌아간다.
- 결정사항과 논의사항 전체를 항상 함께 보여준다. 결정사항만 보여주고
  논의사항을 숨기지 않는다.

## Boundaries

- 이 규칙은 "그럴듯하게 요약해 준다"는 약속이 아니다. 마지막 줄이 실제
  결정사항이 아니면(예: 결론 없이 끝난 논의) 뽑힌 문장도 결정사항이 아닌
  채로 나온다. 이때는 진행자가 연필 아이콘으로 직접 고친다.
- 여러 줄에 걸친 진짜 요약이 필요하면 이 규칙을 확장하는 것이 아니라
  별도로 다시 정한다(아래 Reconsider when 참고).

## Why

처음에는 "논의사항을 회의가 끝날 때 AI가 요약해서 결론으로 보여 달라"는
요청이었다. 무료 LLM(Google Gemini, Groq 등)도 검토했지만, 사용자가 최종적으로
원한 것은 "그냥 마지막 문장을 깔끔하게" 보여주는 수준이었다. 회의 노트를
쓸 때 마지막 줄에 결정사항을 적는 습관이 흔하다는 점에서, 마지막 줄을
그대로 뽑는 것만으로도 실제 결정사항에 가까운 경우가 많다.

AI 요약은 API 키, 비용, 응답 지연까지 데려온다. 기계적 추출은 이 모든 것에서
자유롭고, 결과가 항상 원문에서 그대로 왔다는 것을 사용자가 신뢰할 수 있다.
뽑힌 문장이 마음에 들지 않을 때 사용자가 정정할 방법이 없다는 점은 두
방식이 똑같이 안고 있던 문제였는데, 연필 아이콘으로 직접 고칠 수 있게 해
기계적 추출 쪽에서만 먼저 해소했다.

## Reconsider when

- 마지막 줄이 실제 결정사항과 다른 경우가 반복되어, 손으로 고치는 일이
  너무 잦아진다.
- 사용자가 다시 "진짜 요약"을 요청하면서 무료 LLM 키를 실제로 발급해 온다.

## Still-rejected alternatives

- Anthropic API로 진짜 요약 — 유용하지만 키와 비용이 필요하다. 사용자가
  먼저 무료 대안을 물었고, 이후 "그냥 마지막 문장" 쪽으로 요청을 좁혔다.
- 무료 LLM(Gemini/Groq)으로 요약 — 두 번 제안했으나 사용자가 매번 "그냥
  마지막 문장을 깔끔하게 작성해줘"로 답해, 기계적 추출을 원하는 것으로
  판단했다.
